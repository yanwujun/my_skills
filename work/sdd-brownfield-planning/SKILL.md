# 规划文档模板

从 P2040 多市场适配阶段二提取的结构模板。

## 前置步骤：业务规则提取（条件启用）

### 检测是否可用
检查项目根目录或 PATH 中是否存在 `roam` 命令：
```bash
which roam || (test -f ./roam && echo "./roam")
```

### 如可用，执行以下步骤：
1. `roam business-rules extract` — AST 扫代码，提取 8 类业务规则
2. `roam business-rules summarize` — LLM 语义增强（无 API key 自动降级）
3. `roam business-rules graph` — 构建规则图谱
4. `roam business-rules snapshot --label "基线"` — 保存基线

### 产物用途
提取的业务规则将作为规划阶段的上下文，帮助识别：
- 哪些现有规则可能被本次变更影响
- 哪些模块是高风险区域（规则密集）
- 是否有可复用的已有实现

### 输出
```markdown
## 业务规则基线

**状态：** ✅ 已执行 / ⏭️ 跳过（未安装 business-rule-graph）

### 规则摘要
| 规则 ID | 描述 | 分类 | 涉及模块 |
|---------|------|------|---------|
| R-01 | ... | 状态约束 | XxxService |
| ... | ... | ... | ... |

### 高风险区域
- [列出规则密集或复杂度高的模块]
```

### 如不可用
跳过此步骤，不阻塞后续流程。在规划文档中标注 `⏭️ 跳过（未安装 business-rule-graph）`。

## 必须章节

```
§0  代码现状验证（验证项 | 文档描述 | 代码现状 | 结论 四列表）
§1  总体目标（≤6 条 | 一句话 两列表）
§2  实施策略（ASCII 批次流程图 + 依赖箭头）
§3  批次 A: P0 主链路（目标 + 逐任务：类|路径|改法）
§4  批次 B: P1 合规交互
§5  批次 C: P2 增强运维
§6  待设计冻结项（阻塞项 | 影响范围 | 当前状态 三列表）
§7  跨系统依赖与发布窗口（ASCII 架构图 + 约束表）
§8  工时估算（批次 | 涉及端 | 改造文件 | 新增文件 | 核心难度）
§9  验收勾选总表（按批次分组的 checkbox 清单）
§10 下一步行动（立即|启动前|开发中 优先级排序）
```

## 关键写法

### 任务条目格式
单行三列，信息密度高：
```
| A-2 | ProviderEnterApplyServiceImpl#save | service/providerenter/... | 方法签名增 marketId |
```

### 跨系统约束标注
用 ⚠️ 和 ASCII 图标注跨系统依赖与发布窗口约束。

### 待设计冻结项
只列不可绕过、不设计就无法实施的阻塞项，不列可延后的优化。
