# AI 记忆概念与类比库

> 用于 AI周报视频文稿中涉及「AI记忆」话题时的类比素材和精准度校验。

## 核心机制

AI Memory 的本质：从多轮对话中**选择性提炼**关键信息，存储在外部知识库（知识图谱/向量数据库）中，下次会话时按相关性检索，注入上下文。

关键特征：**选择性（非全量）、提炼（非原文存储）、检索式（非顺序回放）**。

## 类比库

### ✅ 适用的精准类比

| 类比 | 匹配机制 | 适用场景 |
|------|---------|---------|
| 开会记笔记 | 挑重点记 → 下次翻本子回顾 → 不看完整录音也知道上次聊了啥 | 通用，解释 memory 核心逻辑 |
| 客服 CRM 系统 | 每次来电自动弹出客户历史记录：「张先生，上次您反映的是空调不制冷问题」 | mem0 的记忆准确率提升 |
| 私人秘书 | 不是全程录音，而是会后给你一份会议纪要，下次会议前提醒你上次的要点 | 多 Agent 共享记忆 |

### ❌ 不精准的类比（禁止使用）

| 类比 | 为什么不匹配 |
|------|------------|
| 手机云端备份 / 手机克隆 | 全量恢复，不是选择性提炼。用户提出后已修正。 |
| 电脑的「最近文件」列表 | 只是时间排序，没有语义提炼 |
| 微信聊天记录搜索 | 关键词匹配，不是语义理解和知识图谱 |

## 相关项目区分

| 项目 | 定位 | Star | 核心差异 |
|------|------|------|---------|
| claude-mem | Claude 专用本地记忆 | ~85k | 单模型绑定，本地存储 |
| cognee | Agent 通用记忆平台 | ~8.1k | 知识图谱，支持任意 Agent，多格式数据摄入 |
| mem0 | AI 记忆层（SDK/API） | ~40k | 2026.04 新算法 LoCoMo 71→91 分，强调准确率 |

## 集成分析（2026-07-06）

**Cursor + cognee/mem0**：理论可行（通过 MCP），但 Cursor 自带的代码仓上下文+聊天历史已足够强，增益有限。真正有价值的场景：多工具（Cursor + Claude Code + Copilot）共享同一份记忆。

**Hermes + cognee/mem0**：原生支持 MCP，接入可行。Hermes 内置 memory 适合「记住偏好和约定」（2000 字符级），cognee/mem0 适合「成千上万次对话的记忆检索」。当 Hermes memory 容量不足或多 Agent 共享记忆时，值得接入。

## 视频中的正确表述

不要用「全量恢复」「数据迁移」「备份还原」这类词。用：
- 「挑重点记下来」
- 「翻一下上次的笔记」
- 「知道你是谁、你在做什么、上次聊到哪了」
