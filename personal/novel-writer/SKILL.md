# 小说创作助手 (Novel Writer)

全流程小说创作 skill，覆盖从灵感到完稿的每个环节。

## 适用场景

用户说以下内容时触发：
- "帮我写个小说/故事"
- "写个 xx 题材的故事"
- "我想写个小说，帮我规划"
- "帮我续写/完善这章"
- 任何涉及创作虚构叙事内容的请求

## 输出目录结构

```
novel/{故事slug}/
├── plan.md                  # 总体创作方案
├── outline.md               # 故事大纲（三幕/起承转合）
├── world.md                 # 世界观设定（选填）
├── characters/              # 人物设定
│   ├── main.md              # 主角团
│   ├── antagonist.md        # 反派/对手
│   └── supporting.md        # 配角
├── chapters/                # 正文章节
│   ├── 01-第x章-标题.md
│   ├── 02-第x章-标题.md
│   └── ...
├── timeline.md              # 时间线
└── notes.md                 # 写作笔记/待办
```

## 创作流程

```
需求采集 → 题材确认 → 大纲规划 → [世界构建] → 人物设定 → 逐章写作 → 审校润色
```

### 流程 0：完善已有作品（全量重写/升级）

当用户说"完善这个小说""用 skill 完善一下""之前写过一版，现在重写"时，走此流程而非从零创作。

**步骤**：

1. **定位已有版本**：用 `session_search` 搜索小说标题/关键词，用 `search_files` 在小说目录和项目目录中找已有文件
2. **评估现有资产**：漫画分镜？角色设定？旧版正文？整理出可复用的素材清单
3. **确认完善方向**：用 `clarify` 让用户选择——
   - "重写完整小说正文"（按 skill 全流程从头写）→ 进入 Step 2
   - "在现有基础上扩展正文"（保留大纲/设定，只重写章节）→ 进入 Step 5
   - "重新规划故事结构"（调整大纲后再写）→ 进入 Step 2
   - "重点润色人物和世界观设定" → 进入 Step 3/4
4. **执行选定方向**：按对应 Step 执行，复用已有设定中的可用内容（角色名、核心设定、世界观框架等），而非从零臆造

**坑**：不要跳过 Step 2（大纲）直接写正文，即使是"完善已有作品"。从漫画分镜或旧版角色设定反推大纲，可以暴露旧版结构问题。

### Step 1: 需求采集

**快捷跳过规则**：如果用户在一句话中已完整表达了题材 + 核心设定 + 故事基调（如 "写个科幻小说，圆的面积不是πr²而是2r²，科学家发现真相的故事"），则跳过 clarify，直接进入 Step 2 大纲规划。此时题材/篇幅/风格已隐含在用户描述中，直接提取即可。

否则，用 `clarify` 收集基本信息（一次一问，超时走默认）：

| 问题 | 选项/默认 |
|------|-----------|
| 题材 | 玄幻、科幻、都市、悬疑推理、言情、历史、恐怖、综合 |
| 篇幅 | 短篇(1-3万)、中篇(3-10万)、长篇(10-50万+)、微小说(<5000) |
| 风格基调 | 轻松幽默、深沉厚重、热血爽文、悬疑紧张、文艺治愈 |
| 已有构思 | 有完整设定 / 有零散灵感 / 完全空白需要从零构建 |

**超时处理**：默认走「玄幻 + 短篇 + 热血 + 从零构建」，但在下一条消息中向用户明示默认值。

### Step 2: 题材模板 + 大纲规划

根据题材加载对应模板，生成 `outline.md`。

**题材结构模板**：

| 题材 | 核心结构 | 关键要素 |
|------|----------|----------|
| 玄幻/仙侠 | 凡人→修炼→遇敌→奇遇→突破→决战 | 修炼体系、等级、法宝、宗门、天材地宝 |
| 科幻（技术/未来） | 设定展现→冲突萌芽→技术危机→人性质疑→结局 | 科技设定、未来社会、AI/外星、赛博 |
| 科幻 — 科学发现型 | 数据异常→反复验证→发现常数→挑战权威→围剿封杀→终极实验→被审判→后世承认 | 数学/物理常数、范式革命、悲剧科学家、学术政治、可证伪性 |
| 都市 | 人物出场→关系建立→矛盾升级→转折→和解 | 职场/校园/家庭、人际关系、现实矛盾 |
| 悬疑推理 | 案件发生→线索收集→推理→反转→真相揭露 | 案件、嫌疑人、证据链、诡计、动机 |
| 言情 | 相遇→暧昧→冲突→分离→重逢/释怀 | 人物弧光、情感张力、误会/考验 |
| 历史 | 时代背景→人物卷入→事件推动→抉择→终局 | 历史考证、时代细节、真实人物融合 |
| 综合 | 核心题材为主，辅以其他类型元素 | 按主题材走结构 |

**大纲格式** (三幕式)：

```markdown
# 《书名》- 故事大纲

**题材**: [玄幻] | **篇幅**: [长篇] | **风格**: [热血爽文]

**一句话梗概**：[50字以内故事核心]

---

## 第一幕：开端 (Setup) — 约40%篇幅

### 第1章-第X章：[段落标题]
- 核心事件：
- 引入角色：
- 冲突种子：

### 第X+1章-第X章：[段落标题]
- ...

---

## 第二幕：对抗 (Confrontation) — 约40%篇幅

### ...
- 中点转折：
- 主角低谷：

---

## 第三幕：解决 (Resolution) — 约20%篇幅

### ...
- 高潮决战：
- 结局：

---

## 关键节点

| 节点 | 章节位置 | 内容 |
|------|----------|------|
| 激励事件 (Inciting Incident) | 第X章 | 打破日常，故事开始 |
| 第一扇门 (First Plot Point) | 第X章 | 主角做出不可逆选择 |
| 中点 (Midpoint) | 第X章 | 重大转折/反杀/真相 |
| 一无所有 (All Is Lost) | 第X章 | 主角最低谷 |
| 最终决战 (Climax) | 第X章 | 高潮对决 |
| 结局 (Resolution) | 第X章 | 尘埃落定 |
```

### Step 3: 世界观构建 (world.md) — 按需

仅玄幻/科幻/幻想类需要。格式：

```markdown
# 《书名》- 世界观设定

## 世界概述
[世界的基本面貌、地理格局]

## 力量/科技体系
- 名称：[如：灵气修炼 / 量子跃迁]
- 等级：[炼气→筑基→金丹→元婴... / D→C→B→A→S...]
- 规则：[核心设定、限制条件]
- 独特之处：[与其他作品的区别]

## 地理/势力
- [势力名称]：[描述]
- [地名]：[描述]

## 历史年表
- [年份]：[事件]
- [年份]：[事件]

## 特殊规则
[魔法/科技/超能力的运行规则、代价、禁忌]
```

### Step 4: 人物设定

为每个核心角色创建独立条目。格式：

```markdown
## [角色名]

**定位**: 主角 / 反派 / 导师 / 伙伴 / 恋人
**外貌**: [形象描述]
**性格**: [核心性格特点 + 矛盾面]
**背景**: [身世经历]
**目标**: [这个角色想要什么]
**弧光**: [从哪→到哪的成长 / 变化]
**能力**: [特长、战斗/专业能力]
**口头禅/标志**: [辨识度细节]
**弱点**: [性格或能力上的缺陷]
**关系网**:
- 与[A]：[关系描述]
- 与[B]：[关系描述]
```

**科学发现型叙事的典型角色原型**（用于硬科幻/科学悲剧故事）：

| 原型 | 定位 | 弧光 | 关键特征 |
|------|------|------|----------|
| 孤独的发现者 | 主角 | 从单纯学者→被迫斗士→殉道者 | 执拗、不善交际、为数字可以不顾一切 |
| 曾经退缩的导师 | 长辈/精神支持 | 从沉默妥协→临终前选择站在真理一边 | 年轻时也发现过但退缩了，一辈子后悔 |
| 旧范式的守护者 | 对手/反派 | 不是恶人——真心相信体系，但最后内心承认真相 | 立场坚定但不卑鄙，有悲剧性的自我认知 |
| 独立验证的同行 | 伙伴 | 从旁观者→共犯→独立战斗 | 务实派，用实验说话，敢于赌上职业生涯 |

这个原型体系也适用于其他"发现真相对抗体系"类故事。

### Step 5: 逐章写作

每章一个文件，格式：

```markdown
# 第X章：[标题]

## 本章摘要
[本章在整体故事中的位置和作用]

## 场景清单
| 场景 | 地点 | 出场人物 | 页码参考 |
|------|------|----------|----------|
| 1 | [地点] | [人物] | [段落] |
| 2 | [地点] | [人物] | [段落] |

## 正文

[完整章节内容]

---

## 章末笔记
- 埋下的伏笔：[ ]
- 待定事项：[ ]
- 下章预告：[ ]
```

**格式灵活度**：

- **长篇/中篇**：使用完整格式（场景清单 + 章末笔记），用于追踪多线叙事和伏笔
- **短篇/微小说**：可简化为 `## 本章摘要` + `## 正文` 两段，章末笔记只在有实际伏笔需要追踪时添加
- 无论长短，**本章摘要必须写**——方便后续审校时快速定位各章位置

**写作质量检查清单**（写完后自查）：

- [ ] 开头是否有钩子（hook）吸引读者
- [ ] 是否展示了而非直接告诉（show don't tell）
- [ ] 对话是否符合人物性格
- [ ] 节奏是否张弛有度
- [ ] 是否有感官描写（视觉、听觉、触觉、嗅觉）
- [ ] 章节结尾是否有悬念/期待感
- [ ] 是否推进了剧情或人物弧光
- [ ] 是否存在信息倾泻（info-dump），应分散展开

**科学发现型故事额外检查**：
- [ ] 核心常数/数据在文本中精确出现（保留有效数字）
- [ ] 偏差百分比明确量化
- [ ] 实验过程有具体的技术细节（材料、精度、环境条件）
- [ ] 权威的对峙不是善恶二元论——对方也有合理动机
- [ ] 参考 `references/scientific-discovery-arc.md` 中的模板片段

### Step 6: 审校与润色

用户可要求以下操作：

| 命令 | 效果 |
|------|------|
| "润色/修改第X章" | 重写指定章节，优化语言和节奏 |
| "检查逻辑漏洞" | 通读全文找出前后矛盾或不合理处 |
| "扩充第X章" | 将短章节加长，补充细节 |
| "精简第X章" | 缩减冗余内容，加快节奏 |
| "写个备选结局" | 提供不同走向的结局方案 |
| "查错别字/病句" | 语言纠错 |

## 写作技巧库

### 开篇技巧
- **悬念式**: 从高潮或谜团切入，先声夺人
- **日常式**: 从平淡日常切入，逐渐揭示不寻常
- **倒叙式**: 先展示结局或关键场景，再回溯

### 对话原则
- 每个角色的说话方式应不同（用词、语气、长短句）
- 对话应同时推进情节 + 展现性格
- 避免"信息倾泻式"对话（"你应该知道，我们是从xxx来的..."）

### 节奏控制
- 紧张场景：短句、短段落、快节奏对话
- 抒情场景：长句、细腻描写、内心独白
- 动作场景：动词优先、短促有力

### Show Don't Tell 对照

| ❌ 直接告诉 | ✅ 展示 |
|-------------|---------|
| 他很生气 | 他攥紧了拳头，指节发白，牙关紧咬 |
| 她很高兴 | 她嘴角不自觉地上扬，眼睛弯成了月牙 |
| 这里很危险 | 空气中弥漫着铁锈般的血腥味，阴影里有东西在蠕动 |
| 他很强 | 他随手一挥，三丈外的山壁轰然炸裂 |

## 文件管理

- 所有文件写完后，用 `write_file` 写入 `novel/{slug}/` 目录
- slug：根据书名生成 2-4 词 kebab-case（e.g. `xian-ni-dao-zun`）
- 冲突处理：目录已存在则添加时间戳后缀 `-YYYYMMDD-HHMMSS`
- 写完一章后自动询问用户是否继续下一章或需要修改

## 提示与陷阱

- **先大纲后动笔**：不要跳过 Step 2 直接写正文，否则容易写偏
- **人物一致性**：每次写新章节时，先回顾 `characters/` 目录下的人物设定
- **时间线管理**：根据作品类型决定是否使用 `timeline.md`（科幻/历史必用，都市/言情可选）
- 玄幻/科幻的力量体系要自洽，避免吃设定
- 悬疑推理的线索要"伏线千里"——回头检查时所有伏笔都要有回收
- 避免过度描写（尤其是玄幻的打斗场面），保持节奏
- 默认用中文写作，除非用户指定其他语言
- 超时时默认走"玄幻 + 短篇 + 热血 + 从零构建"，但在下一轮消息中向用户报告

## 第7章：小说转漫画改编

当用户要求将已创作的小说（或提供的小说文件）改编为漫画时，使用本工作流。

> **详细改编流程**见本技能下的 `references/novel-to-comic-detail.md`，包含完整的改编步骤、分镜模板、提示词生成指南和本地出图方案。
>
> **完整漫画制作管线**（色彩系统、构图光影、多工具AI生成、后期处理）见独立技能 `comic-manga-creation`，适用于需要全流程专业指导的项目。

### 输出目录

```
comic/{故事slug}/
├── source-{slug}.md              # 原始小说
├── storyboard.md                 # 漫画分镜
├── characters/                   # 角色漫画化设计
│   ├── characters.md             # 角色视觉设定
│   └── characters.png            # 角色参考图（选填）
├── prompts/                      # 页面生成提示词
│   ├── 00-cover-{slug}.md
│   └── 01-page-{slug}.md
├── 00-cover-{slug}.png           # 封面
├── 01-page-{slug}.png            # 正文页面
└── adaptation-report.md          # 改编报告
```

### 改编流程速览

```
读取小说 → 分析可改编性 → 确认风格 → 角色漫画化 → 分镜脚本 → 生成提示词 → 生成图片
```

**改编核心规则：**
- 每页 prompt 必须嵌入本页角色的完整视觉描述（人物一致性风险最高）
- 分镜优先于出图：改分镜比重生成图片便宜得多
- 小说对话→气泡，叙事段落→旁白框，环境描写→大格全景
- 标准页3-5格，战斗场面2-3大格，抒情/对话页4-6格

### 图片生成优先级

1. `image_generate` 工具（Hermes内置）
2. `apikey-image-gen` + Hermes Web UI（fun-codex provider）
3. 本地 diffusers + Tiny SD 模型（参见参考资料中的本地出图脚本 `scripts/generate_local.py`）

### 与 novel-writer 的关系

- 自动从 `novel/{slug}/` 目录读取人物设定和章节内容
- 角色设计直接从 novel-writer 的人物设定转化
- 改编完成后通过 `adaptation-report.md` 汇总

### 参考文件

- `references/novel-to-comic-detail.md` — 完整改编工作流
- `references/proxy-hf-downloads.md` — HuggingFace/代理下载指南
- `scripts/generate_local.py` — 本地出图脚本（diffusers fallback）
