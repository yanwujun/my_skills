## 一、信息安全（~5题）

### 1.1 加密算法三分法

```
加密算法
├── 对称加密（加密解密同一密钥）→ DES、3DES、AES、RC4、SM1、SM4  ← 速度快
├── 非对称加密（公钥/私钥对） → RSA、ECC、DSA、ElGamal、SM2    ← 密钥交换/数字签名
└── 摘要算法（不可逆，验证完整性）→ MD5、SHA-1、SHA-256、SM3  ← 任意输入固定输出
```

**速记口诀：「对非摘」** → 对称、非对称、摘要

### 常见陷阱
- ❌ MD5不是加密算法（不可解密），是摘要算法
- ❌ AES不是非对称加密，是对称加密
- ✅ RSA是非对称加密 ← Q17答案

### 1.2 数字签名流程

```
发送方：原文→MD5摘要→用自己的私钥加密摘要→数字签名
接收方：收到原文+签名→用发送方公钥解密签名→对比自己算的摘要
```

**作用三连：**
1. **防篡改** — 摘要变了比对不上
2. **防抵赖** — 私钥只有发送方有（不可否认性）
3. **身份认证** — 公钥能解开说明是发送方签的

### 1.3 PKI公钥基础设施
- **CA**（认证中心）：签发数字证书
- **RA**（注册中心）：审核用户身份
- **证书**：将公钥与持有者身份绑定的电子文件

### 1.4 主动攻击 vs 被动攻击

| 类型 | 特点 | 常见形式 |
|:----:|------|---------|
| **被动攻击** | 只看不改，不影响系统 | 窃听、流量分析 ← Q18的D选项 |
| **主动攻击** | 动手改，影响系统 | **重放攻击** ← Q18正确答案、篡改、DoS、中间人攻击 |

**速记：「被动只看不动手，主动篡改又重放」**

### 1.5 安全等级（标准化常考）

| 等级 | 名称 | 关键特征 |
|:----:|------|---------|
| D | 最低保护级 | 无任何安全机制 |
| C1 | 自主安全保护 | 用户自主控制访问 |
| C2 | 受控存取保护 | 系统级控制+审计日志 |
| B1 | 标记安全保护 | 数据打安全标签 |
| B2 | 结构化保护 | 形式化安全模型 |
| B3 | 安全域保护 | 安全内核+防篡改 |
| A1 | 验证设计保护 | 形式化验证 |

### 1.6 安全架构战术（案例分析用）

| 需求 | 对应战术 |
|------|---------|
| 防未授权访问 | 身份认证(JWT/OAuth) + 访问控制(RBAC) |
| 防数据泄露 | 传输加密(SSL/TLS) + 存储加密 |
| 防DoS攻击 | 限流(令牌桶) + CDN + WAF |
| 防篡改 | 数字签名 + 完整性校验 |
| 审计需求 | 操作日志 + 链路追踪 |

## 二、系统可靠性（~4题）

### 2.1 可靠性指标

| 指标 | 全称 | 含义 | 口诀 |
|:----:|:----:|------|:----:|
| **MTTF** | Mean Time To Failure | 平均失效**前**时间（第一次坏的时长） | "前" |
| **MTBF** | Mean Time Between Failure | 平均失效**间隔**时间（总运行/故障次数） | "间隔" |
| **MTTR** | Mean Time To Repair | 平均修复时间（修好要多快） | "修" |

**公式：可用性 = MTBF / (MTBF + MTTR)**
- MTBF越大越好（不容易坏）
- MTTR越小越好（坏了好得快）

### 2.2 可靠性计算公式

| 类型 | 图示 | 公式 | 口诀 |
|:----:|:----:|:----:|:----:|
| **串联** | R1→R2→R3 | R = R₁×R₂×R₃ | "串联乘，一个坏全部坏" |
| **并联** | ┌R1┐ R2 └R3┘ | R = 1-(1-R₁)(1-R₂)(1-R₃) | "并联减，一个能用就行" |
| **TMR** | 3个表决2/3 | **R = 3R² - 2R³** | "三模冗余，3R方减2R立方" |

### TMR公式推导（考场上能推出来不用硬背）
```
R系统 = 3个全正常 + 恰好2个正常1个坏
     = R³ + C(3,2)·R²·(1-R)
     = R³ + 3R² - 3R³
     = 3R² - 2R³
```

### 易混淆！TMR ≠ 并联
- 并联是：R = 1 - (1-R)³
- TMR是：R = 3R² - 2R³
- **口诀：并联只有一个能用就行，TMR要至少2个正常**

### 2.3 冗余技术

| 类型 | 备机状态 | 切换速度 | 特点 |
|:----:|:--------:|:--------:|------|
| **热备份** | 一直运行，随时接替 | **最快** | 耗电但切换无感知 |
| **温备份** | 已启动但未处理请求 | 中等 | 折中方案 |
| **冷备份** | 关机状态 | **最慢** | 省电但需手动启动 |

**考试重点：热备份切换速度 > 冷备份 ✅**（Q20的C选项正确）

### 2.4 常见可靠性设计战术（案例分析用）
- **主动冗余**：主备模式，故障自动切换
- **被动冗余**：多个副本并行处理（如K8s多Pod）
- **心跳检测**：定期发心跳，超时判定故障
- **检查点/回滚**：定期保存状态，故障后回滚到检查点
- **错误检测与恢复**：异常捕获、重试机制

## 三、计算机网络（~7题）

### 3.1 TCP三次握手状态（Q14考点！）

```
客户端                          服务器
  │     SYN=1, seq=x             │
  │ ──────────────────────────→  │  客户端→SYN_SENT
  │  SYN=1, ACK=1, seq=y, ack=x+1│
  │ ←──────────────────────────  │  服务器→SYN_RCVD
  │   ACK=1, seq=x+1, ack=y+1    │
  │ ──────────────────────────→  │  双方→ESTABLISHED
```

**状态记忆表：**
| 步骤 | 客户端状态 | 服务器状态 |
|:----:|:---------:|:----------:|
| 发SYN后 | **SYN_SENT** | LISTEN |
| 收SYN+ACK后 | ESTABLISHED | **SYN_RCVD** |
| 最后ACK后 | ESTABLISHED | ESTABLISHED |

### 3.2 四次挥手
```
客户端 → FIN → 服务器（客户端→FIN_WAIT_1）
服务器 → ACK → 客户端（服务器→CLOSE_WAIT，客户端→FIN_WAIT_2）
服务器 → FIN → 客户端（服务器→LAST_ACK）
客户端 → ACK → 服务器（客户端→TIME_WAIT，等待2MSL后关闭）
```

### 3.3 OSI七层 vs TCP/IP四层

| OSI七层 | TCP/IP四层 | 常见协议 |
|:-------:|:----------:|---------|
| 应用层 | 应用层 | HTTP、FTP、DNS、SMTP、POP3 |
| 表示层 | 应用层 | SSL/TLS、JPEG、ASCII |
| 会话层 | 应用层 | RPC、NetBIOS |
| 传输层 | **传输层** | **TCP、UDP** |
| 网络层 | **互联网层** | **IP、ICMP、ARP、RARP** |
| 数据链路层 | 网络接口层 | 以太网、PPP、帧中继 |
| 物理层 | 网络接口层 | 网线、光纤、无线 |

**口诀：「应表会传网数物」→ 应用、表示、会话、传输、网络、数据链路、物理**

### 3.6 指令流水线（计算机组成考点）

**三种冒险类型：**
| 类型 | 含义 | 例子 |
|:----:|------|------|
| **结构冒险** | 硬件资源冲突 | 两个指令同时想用ALU |
| **数据冒险** | 数据依赖导致冲突 | 下一条指令需要上一条的结果（RAW） |
| **控制冒险** | 条件转移导致不确定下一条指令 | **if/else分支预测失败** ← Q16答案 |

**速记：「结数控」→ 结构、数据、控制**

### 3.7 页面置换算法（Q9考点）

| 算法 | 特点 | Belady异常 |
|:----:|------|:----------:|
| **FIFO** | 先进先出 | **会**发生 ← Q9正确答案 |
| LRU | 最近最少使用 | 不会 |
| OPT | 最优置换（理想） | 不会 |
| LFU | 最不经常使用 | 不会 |

**口诀：「只有FIFO会Belady」**
