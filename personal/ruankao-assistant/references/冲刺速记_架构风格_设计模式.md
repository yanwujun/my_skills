# 冲刺速记：架构风格 + 质量属性 + 设计模式

> 综合知识~25题，案例分析必考。**最高优先级章节。**

## 一、7大架构风格

| 风格大类 | 子风格 | 一句话 | 典型场景 |
|---------|-------|--------|---------|
| **① 数据流** | 批处理 / 管道-过滤器 | "数据一步步流过去" | 编译器、Unix Shell(grep\|sort\|uniq) |
| **② 调用/返回** | 主程序-子程序 / 面向对象 / 层次型 / C/S | "一层调一层" | OSI七层、Android系统(驱动→内核→框架→应用) |
| **③ 以数据为中心** | 仓库 / 黑板 | "都来中央查数据" | 数据库、语音识别系统 |
| **④ 虚拟机** | 解释器 / 规则系统 | "造个虚拟机给你跑" | JVM、Python解释器、专家系统 |
| **⑤ 独立构件** | 进程通信 / 事件系统 | "各干各的，发消息通知" | GUI按钮点击触发事件 |
| **⑥ C2风格** | 构件+连接子，上层只能读下层 | "上读下，下不能读上" | GUI系统、可视化编程环境 |
| **⑦ 层次消息总线** | 基于消息总线的层次结构 | "总线挂各层" | 中间件、集成平台 |

### 速记口诀：「水流调中虚独总」→ 数据流 → 调用返回 → 以数据为中心 → 虚拟机 → 独立构件 → C2 → 层次消息总线

### 典型例子对应（考试直接配对）
- 管道-过滤器 ↔ Unix Shell `grep | sort | uniq`
- 层次型 ↔ Android系统 / OSI七层
- 事件系统 ↔ GUI按钮点击触发事件
- 解释器 ↔ JVM / Python解释器
- 黑板 ↔ 语音识别 / 模式识别 / 多个知识源协作
- 仓库 ↔ 数据库管理系统
- C/S ↔ 浏览器-服务器

## 二、6大质量属性 + 战术

### 秒记口诀：「性可安用测易」— 性能、可靠性、安全性、可用性、可测试性、易用性

| 质量属性 | 核心战术 | 案例中使用 |
|---------|---------|-----------|
| **性能** | 资源需求管理、资源仲裁、资源管理 | 缓存、异步、并发、限流、CDN |
| **可用性** | 冗余、心跳检测、主动冗余、故障检测与恢复、熔断降级 | 多副本部署、负载均衡、断路器等 |
| **安全性** | 认证、授权、加密、审计、限流、数据脱敏 | JWT、OAuth2、RSA、令牌桶 |
| **可修改性** | 高内聚低耦合、信息隐藏、接口隔离 | 微服务拆分、依赖注入 |
| **可测试性** | 记录/回放、内置监控、接口暴露 | 日志链路、健康检查端点 |
| **易用性** | 撤销、帮助、国际化、错误提示 | Ctrl+Z、工具提示 |

### 易混淆战术区分
- **限流** → 性能or安全性，**不是可用性战术** ❌
- **心跳检测** → 可用性 ✅
- **熔断** → 可用性 ✅
- **主动冗余** → 可用性 ✅

## 三、质量属性场景6要素

### 口诀：「源激环制应量」

```
刺激源(谁触发的) → 刺激(发生了什么) → 环境(什么条件下) →
制品(影响哪个部分) → 响应(怎么处理) → 响应度量(多快/多少/可用比例)
```

### 标准答题模板（案例分析填空用）

| 要素 | 示例（可用性场景） |
|------|------------------|
| 刺激源 | 系统内部 |
| 刺激 | 服务器进程崩溃 |
| 环境 | 正常操作 |
| 制品 | Web服务器 |
| 响应 | 心跳检测发现故障 → 自动切换到备用实例 |
| 响应度量 | 故障恢复时间 < 30秒 |

## 四、架构评估方法

| 方法 | 全称 | 一句话记 | 主要关注 |
|:----:|:----:|---------|:--------:|
| **SAAM** | 软件架构分析方法 | 最早提出，关注**可修改性** | 可修改性 |
| **ATAM** | 架构权衡分析法 | 多个质量属性**权衡折中** | 性能/可用性/安全/可修改性 |
| **CBAM** | 成本效益分析法 | +**成本效益分析** | 投资回报 |

### 关键概念
- **敏感点(Sensitivity Point)**：某个质量属性的关键决策
- **权衡点(Tradeoff Point)**：影响多个质量属性的点（如加密=安全↑性能↓）
- **风险承担者(Stakeholders)**：所有关心系统的人

## 五、设计模式速记

### 🟢 创建型5个（怎么造对象）

| 模式 | 一句话 | 关键词 |
|------|-------|--------|
| **单例** | 全局只有1个实例 | getInstance() |
| **工厂方法** | 子类决定造哪种对象 ← Q6摸底答案 | "延迟到子类" |
| **抽象工厂** | 造一系列相关对象（产品族） | "配套造" |
| **建造者** | 一步步造复杂对象，可定制步骤 | Builder链式 |
| **原型** | 克隆已有对象 | clone() |

### 🔵 结构型7个（怎么组合对象）— 记前4个高频的

| 模式 | 一句话 | 区分要点 |
|------|-------|---------|
| **适配器** | 接口转换，让不兼容的能一起用 | "转接头" |
| **桥接** | 抽象和实现分离，独立变化 | "两个维度独立变" |
| **组合** | 树形结构，整体和部分一致对待 | 文件/文件夹 |
| **装饰器** | 动态添加功能，比继承灵活 | "套娃加功能" |

### 🟠 行为型11个（对象间怎么协作）— 记前4个高频的

| 模式 | 一句话 | 区分要点 |
|------|-------|---------|
| **观察者** | 被观察者变了自动通知所有观察者 ← Q4/Q5 | "1对N通知" |
| **策略** | 算法可替换，客户端决定用哪个 | "算法换着用" |
| **命令** | 将请求封装为对象，支持撤销/日志 | "操作可撤销" |
| **迭代器** | 统一方式遍历集合，不暴露内部 | 集合遍历 |

### 考法对比：「状态 vs 策略」
- **状态模式**：内部状态变化导致行为变化（自动切换）
- **策略模式**：外部选择不同算法（手动选择）
- **口诀**：状态内在自动，策略外在选择

### 考法对比：「工厂方法 vs 抽象工厂」
- **工厂方法**：一个产品等级结构，子类决定造哪个
- **抽象工厂**：多个产品等级结构，造一系列相关产品
- **口诀**：工厂方法造一种，抽象工厂造一套
