### 真题OCR提取工作流

当需要从扫描版真题PDF（2013-2018）提取内容时，遵循以下流程：

#### 1️⃣ 编写分段提取脚本
- 使用上面的page ranges表格
- 跳过下午II（论文）部分
- DPI=200（平衡速度和精度，每页约10-12秒）
- EasyOCR CPU模式（WSL中gpu=False），初始化约2-3秒
- 每5页save一次.part文件防崩溃
- 用log文件（_ocr_progress.log）记录进度

#### 2️⃣ 运行方式
```bash
# 前台测试（先验证几页）
PYTHONPATH=$HOME/.local/lib/python3.12/site-packages python3 /tmp/ocr_script.py

# 全量后台（推荐：带notify_on_complete+log文件）
background=True, notify_on_complete=True
```
输出日志到 `OUTPUT_DIR/_ocr_progress.log`，可用 `tail -10` 实时查看进度。

#### 3️⃣ 监控进度
```bash
tail -10 "${OUTPUT_DIR}/_ocr_progress.log"
ls -la "${OUTPUT_DIR}/" | grep -v _ocr | grep -v part
```

#### 4️⃣ 已知问题和注意事项
- `MuPDF error: format error: too many kids in page tree` — PDF内部结构问题，不影响OCR渲染
- 「仅供个人学习\n请勿用于任何商业用途」水印会出现在每页底部，OCR会识别出来，属正常现象
- OCR常见错误：'娈量'→'变量'、'〈进制'→'二进制'、'ATAMI'→'ATAM'
- EasyOCR首次使用自动下载模型(~100MB)，约需1-2分钟初始化
- WSL环境不支持GPU加速（gpu=False），但CPU多核并行仍可达10-12s/页
- 完整提取250页约需40-50分钟，建议用后台进程+notify_on_complete

### 流程3：批改用户答题并制定次日计划

**第1步：还原测试题原题**
用户提交答案时可能不在测试题推送的同一会话中。必须先找到原测试题：
- 用 `session_search(query="测试题 YYYY-MM-DD")` 搜索 cron 输出或历史会话
- 或直接读取 cron 输出文件 `~/.hermes/cron/output/<job_id>/<timestamp>.md` 中的 final response
- 或检查 `/home/administrator/晚间测试题_*.py` 等临时文件中的 `content` 变量
- 获取选择题的**标准答案对照表**和案例分析题的**评分要点**

**第2步：解析用户答案（灵活匹配多种格式）**
用户可能用以下任意格式提交答案，必须能解析所有情况：
- 标准格式：`1A 2B 3C 4D 5A`（空格分隔，每题独立）
- 紧凑带句点：`1.C2.D3.A4.B5.A6.不清楚7.不清楚8.B9.B10不清楚`（句点分隔，无空格）
- 纯数字：`1A2B3C4D5A`（完全无分隔符）
- 中文回答：`1.不清楚 2.不清楚`（中英文混合）

**解析规则：**
- 用正则 `(\d+)[.:]?\s*([A-Da-d清楚])` 或逐段拆分
- "不清楚"、"不知道"、"不会"均视为 **答错/0分**（在批改表中标注"未作答"）
- 跳过纯数字序号（如只写"1."没跟答案）
- 如果用户没答完所有题（如只写了1-5），未答题标记为"未作答"并计0分

**第3步：对照标准答案批改**
生成详细批改表：
```
| 题号 | 你的答案 | 标准答案 | 结果 | 知识点 |
|:---:|:--------:|:--------:|:----:|:------|
| 1 | C ✅ | C | ✅ | 主程序/子程序风格 |
| 2 | 不清楚 ❌ | A | ❌ | UML活动图 |
```
- 每题标注三个字段：用户答案、标准答案、正误标记(✅❌)
- 统计正确率：`得分/10 = X%`
- 按照分数段给出定性评价：
  - ≥80%：良好，可按原计划推进
  - 60~79%：需针对性补强错题章节
  - 40~59%：基础不牢，建议放缓进度复习错题
  - <40%：⚠️ 严重薄弱，建议暂停新内容，先巩固基础

**第4步：错题分析 — 归类薄弱领域**
从标准答案的解析文本中提取知识点标签，归类到以下常见薄弱领域：
| 薄弱领域 | 涉及题号 | 常见错因 |
|---------|:--------:|---------|
| 架构风格 | 1, 案例Q1 | 分不清7种风格/说不出区别 |
| 数据库/范式 | 3 | 无损分解判断条件不熟 |
| 设计模式 | 5 | 状态vs策略vs观察者混淆 |
| UML图 | 6 | 活动图vs时序图vs状态图分不清 |
| CAP/分布式 | 7 | CP/AP系统归属记反 |
| 敏捷/软件工程 | 9 | 敏捷宣言4条背反 |
| 架构评估 | 10 | SAAM/ATAM/CBAM混为一谈 |
| 案例分析框架 | 案例 | 没有答题框架/只见树木不见森林 |

列出**前3个最薄弱领域**，告诉用户具体哪些知识点需要回看。

**第5步：错题精讲**
对每道错题，用**精讲模式**（不是抄解析，而是把易混点讲透）：
- 为什么选这个不选那个
- 考点记忆口诀（如"状态内在自动，策略外在选择"）

### 流程4（冲刺期特化）：全方位摸底测试 + 诊断

当距离考试不足7天且用户主动要求摸底时，使用此流程代替日常"晚6点测试题"。

**核心原则**：快速定位弱项，不平均用力，按章节考试占比分配题量。

#### 4.1 出题结构

| 模块 | 题量 | 覆盖知识点 | 说明 |
|:----:|:----:|-----------|------|
| **综合知识选择题** | 25题 | 所有12个章节 | 按考试占比加权：架构~4题、软件工程~3题、OS~3题、数据库~3题、网络~2题、组成~2题、安全~2题、可靠~2题、嵌入~1题、数学~1题、知识产权~1题、新技术~1题 |
| **案例分析题** | 2题 | 架构风格+质量属性（必考）、数据库/高并发/微服务（高频） | 每题设3个子问题 |

#### 4.2 批改诊断

1. **逐题批改表**：用户答案 | 标准答案 | 正误 | 所属章节
2. **统计指标**：已答题正确率、明确表示"不清楚"的数量、各章节掌握度
3. **薄弱等级划分**：
   - 🔴 **严重薄弱**（必须优先补）：正确率<40%且考题占比>10%的章节
   - 🟡 **部分薄弱**（有时间就补）：正确率40%~60%的章节
   - ✅ **已掌握**（保温即可）：正确率>60%的章节

#### 4.3 案例题答题策略

⚠️ **用户偏好：给直接答案，不要做Socratic引导式填空。**
- 当用户说"不会答"或"不知道怎么回答"时，**直接给出完整标准答案**供背诵
- 不通过分步填空、引导式问题来"教"——用户需要的是**答案模板**和**得分点拆解**
- 如果用户想学答题思路，先给完整答案再问"要不要拆解评分标准"

#### 4.4 冲刺记忆材料制作

诊断出薄弱环节后，制作**紧凑型速记材料**，结构如下：

```
# 🔥 [章节名称] 冲刺速记

## [知识点大类1]
| 概念 | 一句话 | 速记口诀 | 典型场景 |
|------|-------|---------|---------|
| ...   | ...    | ...     | ...     |

## 高频考法
- 选择题常见陷阱
- 案例分析答题模板
- 易混淆概念对比表

## 必背公式/数字
- [公式1]（速记推导）
- [口诀]
```

**速记材料制作原则**：
1. 每章不超过一屏（滚动2-3次能看完）
2. 优先覆盖摸底测试中答错的题和"不清楚"的题
3. 每个知识点附一句**速记口诀**（3-7个字）
4. 每个公式附**推导记忆**（不要只给结论）
5. 对比表 > 段落描述（用户一眼能看出区别）

### 判断逻辑

1. 用 `cronjob action=list` 获取所有定时任务状态
2. 检查 `last_run_at` 字段：为空的（从未执行过）→ 错过；`last_run_at` < 应执行时间且 Hermes 当时可能不在线 → 错过
3. 判断 Hermes 是否在线：以上一次用户消息时间为准
4. 列出所有错过的任务，询问用户是否补执行

### 补执行

当用户确认后调用 `cronjob action=run job_id=xxx` 逐个执行错过的任务。仅检查过去24小时内错过的任务。

⚠️ **⚠️ 关键陷阱：cron job prompt中不得包含SMTP代码**
即使技能正文禁止了SMTP，如果cron job prompt中仍留有 `smtplib.SMTP_SSL('smtp.qq.com', 465)` 或QQ邮箱授权码，cron任务执行时仍会尝试发信——浪费计算资源且可能触发安全扫描拦截。
- 创建或修改cron job prompt时，**最后一步必须是**：`输出测试题内容即可，系统会自动deliver到QQ。`
- **绝不能写**：`最后调用 Python 将内容发送到 QQ 邮箱` + smtplib 代码
- 如果cron job prompt已有SMTP代码，用 `cronjob action=update job_id=xxx prompt=新prompt` 移除
- 当前已知有问题的cron job prompt：`软考-晚间测试题`（job_id: 087d233b3317）、`软考-早间知识点学习`（job_id: 79651b456508）—— 两者都可能包含SMTP残留代码
