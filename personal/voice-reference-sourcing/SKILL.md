# 零样本 TTS 参考音色素材获取

CosyVoice 类零样本复刻的音色 90% 由参考音频(prompt)决定。要"老人/小孩/某类嗓音"时，
**找一段真实人声当 prompt 比指令+后处理硬凑有效得多**：指令只能调情绪/语速，改不了声线底子；
过度后处理（降音高 >5% + echo）会变"怪兽音"（实测教训）。

## 触发条件

- 用户要特定嗓音（老人/小孩/方言/沙哑）但现有音色库没有
- 需要给零样本 TTS 换"声线底子"
- 典型场景：散文诗视频的老年角色、有声书角色、配音模仿

## 素材要求

- **3-10 秒连续说话**（零样本复刻最佳窗口，实测 8-9s 最佳）
- 干净人声（无音乐/环境音/水印片头）
- 与目标语种一致（中文要普通话；方言参考会带口音）
- 连续朗读/讲述 > 采访短语回答（1-3s 的答话不够做参考）

## 工作流（实测 2026-08）

1. **B站搜索 API**（web_search 易被 SEO 垃圾污染，直接调 API）：
   ```bash
   curl -s -H "User-Agent: Mozilla/5.0" \
     "https://api.bilibili.com/x/web-interface/search/type?search_type=video&keyword=<URL编码>&page=1"
   ```
   好关键词：`百岁老人 采访 说话` / `老人 读信` / `大爷 朗诵` / `老人 讲述 一生`。
   避开：纪录片式采访（老人只答短语或方言）、多角色配音喜剧（不是真人独白）、带字幕组水印的搬运视频（"字幕byXX"）。

2. **YouTube 搜索**（补 B站不足）：
   ```bash
   yt-dlp "ytsearch5:关键词" --print "%(id)s | %(title)s" --no-playlist --skip-download
   ```
   **CCTV《朗读者》类节目的普通参与者是理想素材**（普通话 + 连续朗读 + 非名人 + 情感自然），
   例如"74 岁老人给老伴儿念信"。

3. **下载音频**（仅音轨）：
   ```bash
   yt-dlp --proxy http://127.0.0.1:8888 -f "ba/b" -o out.%(ext)s <url>
   ```

4. **定位干净人声段**：
   ```bash
   ffmpeg -y -i in.webm -ar 16000 -ac 1 tmp_16k.wav
   # faster-whisper 转写带时间戳, 找 3-10s 连续叙述段
   ```
   判读信号：转写乱码 = 方言（放弃）；出现"字幕byXX" = 水印片头（跳过）；
   长视频转写慢 → 用 `vad_filter=True` 且后台跑。

5. **裁剪参考音频**：
   ```bash
   ffmpeg -y -ss <start> -t 8 -i src -ar 24000 -ac 1 <name>_prompt.wav
   ```

6. **生成变体试听 + 质检**：换 prompt 字段跑 TTS 任务，faster-whisper 转写验证：
   ① 内容与原文一致 ② **指令文本未出现在转写里**（小模型会把长/否定式指令读出来，指令必须简短肯定式）。

## 法律边界（《民法典》1023 条：声音参照肖像权保护）

- 参考谁的声音，生成的就是谁的声线——**未经许可用他人声音合成内容 = 侵害声音权**
- 已故名人（如孙敬修）：声音权由继承人享有，发布高风险，仅限私用
- 普通老人（节目参与者/路人）：风险较低但仍未授权，发布前提醒用户
- **最安全：用户自己/家人录 8 秒**，零风险
- 自娱自乐不发布 ≈ 无风险

## 参考资产惯例

- 命名：`<描述>_prompt.wav`，24kHz 单声道，放模型 assets 目录统一管理
- 保留来源备注（谁的声音/哪个节目），方便法律评估
